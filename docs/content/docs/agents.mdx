## JSON mode

Pass `--json` to any command:

- the result is one JSON document on **stdout**
- progress is JSON lines on **stderr**: `{"event":"step","message":"extracting Setup.zip"}`, `{"event":"progress","done":123,"total":456}`
- errors are a JSON line on stderr, with exit code 1: `{"event":"error","message":"...","causes":[...]}`

```bash
omavn --json install ~/Downloads/game.zip | jq .id
omavn --json list | jq -r '.[].id'
omavn --json run dies-irae --print   # the exact program, argv, env, cwd
```

<Clip name="cli-agents" alt="Terminal recording: omavn --json list piped through jq, omavn --json run --print showing the launch program and environment, and an unknown game failing with exit code 1" />

Nothing prompts in JSON mode or without a terminal: commands that would ask (`run` or `remove` without a game, `remove` without `--yes`) fail with a message instead. Only `omavn gui` ever opens a window, and only because you asked for it.

```bash
omavn --json list dies --sort recent -n 5   # search
omavn --json                                # summary: count and recent games
```

## Building on omavn

The CLI is a thin layer over the `omavn-core` crate. Launchers, GUIs, and library managers can use it directly:

```rust
use omavn_core::{Paths, install, launch, library, report::Silent};

let paths = Paths::from_env()?;
let game = install::install(&paths, &install::Options { source: "Himanatsu_final.zip".into(), ..Default::default() }, &Silent)?;
let spec = launch::game(&paths, &game, None, &[], &Silent)?;
spec.command().spawn()?;
```

Implement `Reporter` to render progress your own way. Game manifests are plain TOML in `~/.local/share/omavn/games/*/game.toml`, so tools in any language can read the library.
